High-Performance Unity: Writing Allocation-Free C# and Leveraging the Burst Compiler

Practical techniques for eliminating GC allocs in hot gameplay loops, struct layout optimization, and SIMD execution.

August 4, 2026

Topic

Unity Optimization

Stack

  • C#
  • Unity 6
  • Burst
  • C# Jobs
  • Profiler

In high-framerate action games and complex simulation engines, garbage collection pauses are the mortal enemy of smooth frame delivery. Even a 5ms GC spike during an intense boss fight or camera transition instantly breaks immersion.

Over the past several years developing gameplay systems in Unity, I’ve established a strict set of architectural rules for writing zero-allocation hot paths that allow games to run locked at 60–144 FPS across any hardware.

1. Identifying Hidden Allocations

Most C# developers don’t realize how many innocent-looking operations trigger heap allocations under Mono or IL2CPP:

  • LINQ queries: .Where() and .Select() allocate enumerators and state machines on the heap. In Update() or FixedUpdate(), LINQ is strictly banned.
  • Foreach loops over non-struct collections: Boxing interface enumerators.
  • Delegate & Lambda captures: Passing an anonymous lambda that captures local variables allocates a closure object on every invocation.
  • String concatenation & formatting: $"Score: {score}" allocates a new string. Use custom struct formatters or cached string tables instead.
  • Unity API calls: gameObject.tag == "Enemy" allocates string buffers; use gameObject.CompareTag("Enemy"). Accessing .materials clones array instances; use .sharedMaterial.

2. Transforming Object Hierarchies to Flat Native Arrays

Standard Unity architectures scatter game state across thousands of individual MonoBehaviour instances. Each instance is a separate heap allocation, meaning cache lines are repeatedly trashed when iterating through them sequentially.

By restructuring entities into contiguous value-type structs stored within NativeArray<T>, data sits tightly packed in memory. The L1/L2 CPU caches can preload sequential blocks, accelerating processing by orders of magnitude.

3. The Power of Burst Compilation

Unity’s Burst compiler transforms a subset of C# (High Performance C# / HPC#) directly into optimized LLVM assembly targeting machine SIMD registers (AVX2, NEON):

[BurstCompile(FloatMode = FloatMode.Fast, FloatPrecision = FloatPrecision.Standard)]
public struct TrajectorySimulationJob : IJobParallelFor
{
    [ReadOnly] public NativeArray<float3> Positions;
    [ReadOnly] public NativeArray<float3> Velocities;
    [WriteOnly] public NativeArray<float3> OutPositions;
    public float DeltaTime;

    public void Execute(int index)
    {
        OutPositions[index] = Positions[index] + Velocities[index] * DeltaTime;
    }
}

With Burst, numerical math loops achieve parity with hand-tuned C++ vector intrinsics. In simulations like Omnith, shifting spatial collision queries and agent steering into Burst-compiled Jobs reduced CPU frame time from 16.4ms down to 1.1ms.

Summary Checklist

  • Profile continuously with the Unity Deep Profiler and Memory Profiler.
  • Ensure GC.Alloc shows 0 B per frame during core gameplay.
  • Prefer structs, object pooling, and NativeContainers over frequent instantiation.
